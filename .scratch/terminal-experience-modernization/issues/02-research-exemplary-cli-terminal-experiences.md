# Research exemplary open-source CLI terminal experiences

Type: research
Status: resolved

## Question

Which maintained open-source CLIs provide the strongest applicable patterns
for vivid forms, finite-work progress, semantic completion transcripts,
failure presentation, and long-running lifecycle logs, and which concrete
patterns should ycy adopt or reject without copying product-specific behavior?

## Answer

Use Dagger as the primary architectural reference for finite Live View and
durable Interaction Transcript separation, Gum and GitHub CLI for vivid Charm
v2 forms and stream-safe product integration, Pulumi for semantic progress and
failure ordering, and Docker Compose for line-oriented Lifecycle Logs. Adopt
their state and output-ownership patterns, but keep every ycy command's phase
structure and wording independent; do not copy trace trees, resource tables,
subprocess-driven forms, or full-screen service dashboards. Full evidence and
source citations are in
[`02-exemplary-cli-terminal-experiences.md`](../research/02-exemplary-cli-terminal-experiences.md).
